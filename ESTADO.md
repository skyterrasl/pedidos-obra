- **Alta de usuarios desde la app** (jul-2026, v27): el admin crea cuentas él mismo (Gestión → Usuarios → Agregar). Truco clave: `createUserWithEmailAndPassword` loguea automáticamente a la cuenta nueva, así que el alta corre en una **instancia secundaria de Firebase** (`firebase.initializeApp(cfg, "alta-usuario")`) que se cierra y se borra al terminar — la sesión del admin no se toca, y el perfil se escribe desde esa instancia para que el uid coincida y las reglas lo acepten sin habilitar escritura de perfiles ajenos. También botón "Contraseña" (mail de reset vía `sendPasswordResetEmail`). Los códigos de invitación siguen funcionando como alternativa.
- Gotcha de las reglas: **nadie puede borrar su propio perfil** (`delete: esAdmin() && auth.uid != uid`), pensado para no quedarse sin admin. Consecuencia práctica: una cuenta de prueba creada por script NO se puede autolimpiar — su perfil queda huérfano y lo tiene que borrar Iván desde Gestión. Al probar altas, usar un nombre inconfundible tipo "ZZ BORRAR".
- **Sin Cloud Functions** (plan Spark): no hay forma desde el cliente de borrar la cuenta de Auth de otro. Borrar el perfil sí bloquea el acceso (la app cierra sesión si no encuentra perfil), pero el email queda registrado en Firebase y no se puede reutilizar para un alta nueva.
